## TODO-2：loadBatch

输入topics为所有议题ID；返回Audience(去重人员Set, 本方法SELECT次数)，不要把Service里已有那次查议题计入。

按这个步骤写：

1. 建TreeSet或HashSet和从0开始的查询计数。
2. for循环每次步进500，用subList截取本批，结束位置用min防越界。
3. 本批每个ID生成一个?，逗号连接，拼 `SELECT person_id FROM topic_attendee WHERE topic_id IN (...)`。

5. 返回new Audience(people,count)。空topics返回空集合/0，不发送IN()。

JdbcTemplate会帮你管理连接、语句和ResultSet；不要手写关闭Spring的数据源，也不要字符串拼接参数值。

## TODO-3：createPool

用new ThreadPoolExecutor手写七参数，返回值由Spring注册为共享Bean：

1. core/max使用传入值，不能写死8，因为饱和实验传的是1/1。
2. keepAlive=30，unit=TimeUnit.SECONDS。
3. ArrayBlockingQueue容量使用传入capacity。
4. ThreadFactory用AtomicInteger编号，线程名meeting-notify-N。
5. RejectedExecutionHandler先rejected.incrementAndGet，再抛RejectedExecutionException。不要执行r.run，也不要静默丢。

验收：GET /api/lab/pool，不再报TODO-3；正常初始拒绝0。然后配合TODO-4跑饱和场景。

Spring采用Lazy Bean：未补完该方法时应用仍能启动；首次访问并发/线程池接口才调用它。修改代码后要重启使Bean重建。

## TODO-4：safeSend

## TODO-5：parallel

输入是人员集合、尝试次数、是否注入故障，以及**Spring应用共享的pool**。

1. 建Map<Long,Future<Outcome>>和最终List<Outcome>。
2. for每个人submit Callable，任务调用safeSend；提交时单独catch RejectedExecutionException，为这个人追加REJECTED结果，其余继续。
3. 全部提交后再遍历Future.get并收集，不要边submit边get变回串行。
4. get抛ExecutionException代表没被safeSend隔离的意外异常，可包装IllegalStateException；不要假装成功。
5. catch InterruptedException：取消本次Map里的所有Future（true）、pool.purge、恢复Thread.currentThread().interrupt，再抛出。
6. 其他异常退出也取消本次未完成任务，避免后台遗留。
7. **不得在请求结束时pool.shutdown/shutdownNow**。它服务其他请求，Spring负责应用停机销毁。本次取消也只针对本次Future。

验收：POST /api/meetings/1/notifications/parallel，300成功；与serial名单一致。加 `?injectFailure=true` 应283成功/17失败；不传persist，所以此时不需要日志代码。再查GET /api/lab/pool确认池仍可复用。

单元测试ReferenceStepsTest给出了拒绝、失败隔离、中断的检查方式；默认测试验证的是答案类，不会把未写的PracticeSteps自动判通过。你的实现以practice接口实测为准。

## TODO-7：writeBatch（先写这个，再组合失败重试）

输入outcomes与meeting；每100条真正多VALUES、每批一个事务。

1. 每100条subList，拼一个或多个(?,?,?)。
2. 建List<Object>，每条依次加入meeting、o.personId()、o.status()。
3. SQL前半：`INSERT INTO push_log(meeting_id,person_id,status) VALUES ...`。
4. 后半采用MySQL8行别名：`AS incoming ON DUPLICATE KEY UPDATE status=incoming.status,create_time=CURRENT_TIMESTAMP`。
5. 每批用 `transactions.executeWithoutResult(status -> jdbc.update(sql,args.toArray()))`。
6. JdbcTemplate与TransactionTemplate共用Spring事务连接；SQL异常向外抛出，模板自动回滚本批。别catch后吞掉异常。上一批已提交不会一起回滚。

这里用TransactionTemplate让批次事务边界直接可见，避免在同一个类里自调用@Transactional导致代理未生效。不必自己获取连接或setAutoCommit。

验收：POST /api/lab/log-benchmark，三轮三种方案各300条，batch每轮3SQL/3事务；然后POST /api/lab/locks，观察deadlocks=1及诊断。锁的搭建代码已提供，重点读懂反序加锁和1213回滚。
