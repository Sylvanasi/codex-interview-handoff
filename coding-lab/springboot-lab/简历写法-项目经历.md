## 二、简历版要点

**跨系统推送：两层幂等**

- 自研 **Spring Boot 3.5** 工程（内嵌 Tomcat、`java -jar` 可执行包），用 mock 上游复现跨系统推送的 **幂等** 与 **凭证复用**，把结论跑成可当场演示的代码。
- 基于 **Redis `SETNX` 占位 + TTL** 与 **MySQL 唯一索引** 做两层幂等，实现**防重复推送**；20 线程并发推同一张单，对方只收到 **1** 次，其余 19 次在本地被拦下。
- 基于 **Lua 脚本**把"比对 owner + 删除"合成一条原子命令释放占位，解决"检查通过后、删除前 key 被别人抢占"（**TOCTOU**）导致的误删。
- 把响应超时按**未知状态**处理：不直接重试，先调查单接口确认，再由 **`@Scheduled` 对账任务**扫描 `IN_PROGRESS` 超时记录收尾，保证**不漏推**。
- 调用侧显式配置**连接超时 + 读超时**，并把 `ResourceAccessException` / `RestClientResponseException` 翻译成"可重试 / 不可重试"两类，避免下游挂掉时线程被占满造成**故障扩散**。

**统一待办聚合：JUC 线程池**

- 基于**手写 `ThreadPoolExecutor`**（核心 4 / 最大 8 / **有界队列** 16 / `CallerRunsPolicy` + 拒绝计数）并发聚合 4 个业务系统的待办，替换串行拉取，把 **门户首屏待办加载** 从 **{待补:ms}** 降至 **{待补:ms}**（降幅 **{待补}%**）。
- 超时控制用**整页时间预算**（统一 `deadline`）而非"每个上游各等一次"，保证**门户首屏待办加载**在最坏情况下仍收敛在 **{待补:ms}** 以内。
- 基于 **`Future.get(timeout)` + 单系统异常降级**实现**局部降级**：单个上游报错或卡死只降级该系统，其余照常返回，把单系统故障的影响面从"整页失败"压到 **{待补:个系统}**。
- 通过 **`GET /api/pending/pool`** 暴露 `activeCount` / `queueSize` / `rejectedCount` 等线程池指标，用于容量评估与告警。

**工程与验证**

- 沉淀 **12 个自动化用例**（含 20 线程并发幂等、唯一索引兜底、真 Redis 上的 `SETNX`/Lua 语义），用 **`@ConditionalOnProperty`** 实现"内存实现 / 真 Redis + MySQL"按 profile 切换，零依赖也能跑。

> 加粗规则：技术关键词与数据指标加粗；`{待补:...}` 是**必须你亲自填**的真实数字（见第四节），没填之前先别投。

## 三、面试追问准备

每条要点后面那个"最容易被追的一问"，先自己答一遍：

| 要点 | 可追问 |
|---|---|
| 两层幂等 | 只保留 Redis 会怎样？只保留数据库会怎样？为什么两边都要？ |
| Lua 释放占位 | 为什么不用 `GET` + `DEL` 两步？只加 owner 不用 Lua 行不行？只加 Lua 不加 owner 行不行？ |
| 超时=未知状态 | 你怎么知道对方到底收没收到？查单接口也超时了怎么办？ |
| 对账任务 | 对账扫描的阈值怎么定？重复对账会不会造成二次推送？多实例部署时对账任务会不会重复跑？ |
| 线程池参数 | 核心线程数为什么是 4 不是 8？队列为什么必须有界？拒绝策略为什么选 `CallerRuns` 而不是 `Abort`？ |
| 整页时间预算 | 为什么不用"每个上游各给 timeout"？那样写最坏耗时是多少？ |
| `cancel(true)` | 超时之后那个任务真的停了吗？线程什么时候才释放？ |
| 降级取舍 | 为什么选"局部降级"而不是"整页失败"？什么业务场景反而应该整页失败？ |

## 五、这条经历能写、不能写什么

**能写**：上面全部内容。因为它们都真实存在于这个工程里，你打开 IDE 就能指给面试官看，每一行都能解释。

**不能写**：把这几项说成是在某个**客户项目**里做的。你的客户项目（深圳巴士、罗格朗、融资租赁等）用的是蓝凌 EKP 老栈，不是 Spring Boot；说成是项目里做的，面试官只要问一句"你们项目怎么打的包、pom 里引了什么"就会兜不住。

**后来可以升级成"项目经历"的唯一条件**：你在某个真实项目里真的用 Spring Boot 做了一次同类事情（哪怕是内部小工具）。那时把这条的内容搬过去，数字换成真实环境的，才算数。
