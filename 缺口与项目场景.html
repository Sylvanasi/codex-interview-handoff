一、本轮缺口（第一题 · 金蝶云星瀚）

考察点现状面试官会怎么追你要补成什么话
链路方向✅ 对 — 双向要一句话说清：采购侧推附件进 OA；OA 审批完成后反向推台账给金蝶。
协议与接口形态⚠️ 没提 "你给金蝶的接口长什么样？" HTTP + REST，请求体 multipart/form-data（JSON 部分 + 多个文件部分），返回统一结构 {code,msg,data}。
回执⚠️ 没提 "你返回什么给他？他怎么知道成没成？" 同步返回业务单号 + 处理结果；失败要能让人拿去重推，而不是只回一个 200。
业务主键⚠️ 没提 "两边怎么对上同一张单？" 贯穿全链路的业务单号（采购单号 / 合同编号）——它同时是幂等键、对账键、排查用的检索键。
代码落点⚠️ 不够具体 "接口是哪个类？路径是什么？" 要能报出控制器 / 服务类名和 URL 路径，并说清监听器挂的是产品的哪个扩展点。
token 缓存✅ 对 "过期时间怎么定？" 已经在讲：单例 + 静态变量 + 超时时间 + 惰性刷新。补一句过期时间怎么来的（对方返回的 expires_in 里减去安全余量，比如提前 5 分钟换）。
并发刷新⚠️ 缺一句 "第二个线程进来会不会又刷新一次？" 检查"是否过期"这一步必须在锁内，所以第二个线程进来时看到已经是新的，不会重复换取。这句话要主动补上。
多实例部署⚠️ 没提 "你部署几个节点？每个节点各换一份 token 会怎样？" 真实边界：进程内缓存每个节点各一份，会各换一次；对方若对同一凭证有并发限制就会出问题，所以要把 token 放进 Redis 共享。
401 兜底⚠️ 没提 "凭证被对方提前失效呢？" 业务接口返回鉴权失败时：清掉本地缓存 → 强制换一次 → 原请求重试一次（只重试一次，防打转）。
异常分类⚠️ 太笼统 "超时和参数报错，你的处理一样吗？" 分三类：超时 / 5xx → 可重试；4xx 字段校验不过 → 不重试，落错误表 + 告警；附件超限 → 提前在入口校验并明确回绝。
重复推送❌ 方向错 "你自己怎么防重？" 原做法是等对方报错才知道重复 —— 被动。改成主动：本侧幂等台账 + 对方按单号幂等，双保险。
幂等实现⚠️ 差两点 "先查再写，两个请求同时进来会怎样？" 要用 SETNX 原子占位，不能先 exists 再 set；Redis 之外还要有 DB 唯一约束兜底。

四、这条经历在面试里怎么说（60 秒版）

"我在深圳巴士集团那个项目里负责和金蝶云星瀚的对接，两个方向。采购系统那边把合同和多附件推给我们 OA，我提供一个 REST 接口收 multipart 报文，JSON 部分存合同表，附件单独落库，返回带业务单号的回执；用户在 OA 里起合同时可以把这个合同拉出来选中填充，走完审批再由流程结束的事件监听器把合同字段和附件反向推给金蝶台账接口。

最麻烦的是推送侧的一致性。金蝶那边同一张单推两次会报错，我一开始是等它报错才发现重复，很被动。后来改成主动幂等：用业务单号做幂等键，推送前先在 Redis 里 SETNX 占位并设过期时间，推送成功再改成完成标记，明确失败才释放占位允许重试；响应超时这种未知状态不直接重试，先调对方的查单接口确认。Redis 之外还留了一道数据库唯一约束兜底，因为缓存会过期、会重启。"

这段里的幂等部分，等你把 idempotent-push 4 个关卡跑通、能自己解释每一关的现象，才写进简历。

五、Spring Boot 实验台（springboot-lab）

位置：coding-lab/springboot-lab。建它的唯一原因：你的简历上一处 Spring Boot 都没有，8 年 Java 却没有 Boot，面试官一定会问"你们用什么框架、怎么发布的"。

它同时把两个高风险说法变成了能跑的代码：token 周期性缓存与鉴权复用、幂等与重复推送治理。本机实测：编译 16 个源文件、5 个业务用例全绿（Spring Boot 3.5.0 + JBR 25，测试 4 秒）。

实验怎么跑预期结果
凭证缓存连续 5 次 POST /api/token/warm真实换取次数仍是 1
并发取凭证POST /api/token/parallel?threads=5050 个线程，只换 1 次
401 自愈先推一张单 → POST /mock/kdx/revoke-tokens → 再推新单清缓存换一次后重试成功，只重试一次
串行幂等同一张单 push 两次第二次 SKIPPED，对方只收到 1 次
20 并发幂等POST /api/contracts/X/push-parallel?threads=20对方只收到 1 次
超时查单POST /mock/kdx/config?timeoutAfterSuccess=true 后再推返回 TIMEOUT_CONFIRMED，不重复推送

搭这个工程时踩到的三个坑（面试可以当"我遇到过什么"讲）

  • XML 注释里不能出现 --，拿横线当分隔线会导致 Maven 直接报 POM 解析失败。
  • 全局异常处理里只写 @ExceptionHandler(Exception.class) 兜底，会把框架的 401 变成 500 —— 于是"清缓存重试"这条自愈路径永远不触发。修法是显式放行 ResponseStatusException 并保留原状态码。
  • success 和 duplicate 同时为 true 时，先判 success 就永远看不到"对方替我兜了底"的信号。判断顺序本身就是业务语义。

环境要准备什么

组件要不要说明
Tomcat不需要Spring Boot 内嵌 Tomcat，main 方法直接起服务，不用装、不用打 war。这是必考面试题。
Maven不用单独装IDEA 内置了，打开 pom.xml 会自动下载依赖。
JDK8 不行本机装的是 Corretto 8，跑不了 Spring Boot 3.x（最低要求 17）。两条路：把 IDEA 自带的 JBR 25 加成 SDK（路径 /Applications/IntelliJ IDEA.app/Contents/jbr/Contents/Home），或装 JDK 21 LTS（面试答这个最稳）。终端跑 mvn 时 JAVA_HOME 也要指向 17+。
Redis要下一步把内存台账换成真 Redis 才能讲出分布式幂等。OrbStack 已经装了 docker：docker run -d --name interview-redis -p 6379:6379 redis:7-alpine
MySQL已有（3306）建独立库 interview_lab，别和业务库混；幂等表要建唯一索引，这是"缓存之外的最后一道防线"。
